# 离线字幕缓存 · 可行性分析

> 日期：2026-10-13 ｜ 需求方：Ari ｜ 分析基准：仓库 HEAD（versionName 2.3.x / code 1006 之后的工作树）
>
> 需求原文：把已经在线抓到的作品的字幕缓存到本地，后续在断网的时候播放同轨的时候读取本地字幕。

---

## 0. 结论

**可行，且是"便宜活"** —— 整条链路不需要新增任何 hook 采集点，写入与读取两侧需要的全部数据都已经在现有管道里流动。

- **机制一句话**：在线时把「字幕 JSON 原文 + 播放身份指纹 `(trackCount, durationMs, currentIndex)`」落盘；断网时换轨通知带着同样的指纹到来，按指纹查盘、命中就直接走现有 `loadFromJson` 路径加载。
- **最大残余风险**：写入时可能被「标签竞态」盖错轨（有缓解栈，见 §5.4），以及两个需真机验证的假设（§10 的 A1/A2）。
- **工作量**：Phase 1 核心（无 UI）约一个发版轮次；Phase 2 设置页开关/清理再一轮；Phase 3 增强可选。

---

## 1. 需求与场景

- **用户故事**：Ari 在断网（飞行模式）环境下播放**已下载**的作品，希望悬浮字幕照常显示。
- **前提已核实**：DLsite Sound 官方支持作品下载与离线播放（官网 LP 明示 "Offline Playback"），场景成立。
- **断网现状**：`NetworkHook` 三条通道都等不到字幕 JSON ⇒ 走待确认/裁决流 ⇒ 软裁决后三处 UI 显示「无字幕」或空窗（`NO_SUBTITLE_GRACE_MS_CACHED` = 15s）。

## 2. 现状盘点（能白嫖的基建）

| 能力 | 现有实现 | 本功能复用处 |
|---|---|---|
| 字幕抓取 | `NetworkHook` 三通道；2.20.2 起主通道 = `Response.Builder.build()` + 非消费 peek | `submit()` 已同时拿到 **JSON 正文 + workKey**，写入点零改造成 |
| 作品键 | `PlaylistKey.workKeyOf(url)`（砍查询串 + 砍文件名） | 索引条目的作品归属 |
| 播放身份 | `PlayerSourceHook.makeIdentity(tc, durMs, idx)`；状态 Map 输出 `trackCount/duration/currentIndex/...` | **指纹即身份**，换轨通知 `onTrackChanged(...)` 已把完整身份当参数传下来 |
| 内存版"缓存恢复" | `SubtitleRepository.tryResumeFromCache`（code 980 + 1004/1005/1006 四条认领路径） | 本功能就是它的**磁盘持久化扩展**；接入点天然排在它后面 |
| 落盘先例 | `NetLogFile` → 宿主 `getExternalFilesDir(null)` | 存储位置有实证，无权限问题 |
| 原子写先例 | `ConfigStore.writeJsonAtomic`（临时文件 + 原子替换） | 索引文件防写坏 |
| 配置 / 广播 | `SubtitleConfig` + `Protocol`（三进程广播契约） | Phase 2 的开关与「清理缓存」命令 |

**关键洞察**：`onTrackChanged(where, indexVerified, newIdentity, newSelection)` 收到的 `newIdentity` 就是把 `(tc, durMs, idx)` 打包好的 long——**磁盘查询的键就是现成的**，一种打包口径都不用新造。

## 3. 总体方案

```
在线时 · 写入                              断网时 · 读取
┌─────────────┐   ┌──────────────────┐   ┌──────────────┐
│ 宿主播放音轨  │ → │ NetworkHook 抓到  │ → │  写入磁盘缓存 │
│ (已下载/在线) │   │ 字幕 JSON+workKey│   │ JSON+索引     │
└─────────────┘   └──────────────────┘   └──────┬───────┘
                                                │ 落盘
                                     ┌──────────▼───────────┐
                                     │ 字幕磁盘缓存          │
                                     │ 宿主 App files 目录   │
                                     │ 指纹=(tc,durMs,idx)  │
                                     │ LRU 上限 · 在线重播自愈│
                                     └──────────┬───────────┘
                                                │ 命中
┌─────────────┐   ┌──────────────────┐   ┌──────▼───────┐
│ 断网播放     │ → │ 状态 Map 权威身份 │ → │ 指纹命中 →    │
│ 下载作品     │   │ (tc,dur,idx)     │   │ loadFromJson │
└─────────────┘   └──────────────────┘   │ → 三处 UI 恢复│
                                          └──────────────┘
```

三段各自只有一个职责：

1. **写入（在线）**：`loadFromJsonArrayInternal` 成功后，把 JSON 原文 + 当时的选择键 `(tc, idx)` + workKey 异步落盘；`duration` 事后补盖（§5.1）。
2. **索引**：单文件 `index.json` + 每轨一个 JSON 文件；LRU + 容量上限；损坏容忍。
3. **读取（断网）**：换轨通知到达 → 内存缓存未命中 → 磁盘按指纹查 → 命中则异步读文件、走 `loadFromJson(text, workKey, fromDisk=true)`。

## 4. 核心难点：断网时"你在播哪部作品的哪条轨"

断网后没有任何网络侧证据（URL 不出现了），必须从**本地就能读到的量**里认出音轨。四个候选：

| 方案 | 依据 | 断网可用 | 判定 |
|---|---|---|---|
| A. 字幕 URL / 作品键 | 在线抓取那一刻才有 | ✗ | 只能当**写入时**的标签，不能当读取时的判据 |
| B. 媒体源 URI（hook 播放器设源） | 播放时设置的源 | 可能（下载版是本地文件路径） | R8 形状匹配有真实风险（964/965「挂上零命中」教训）；下载文件路径格式未知 ⇒ **留作 Phase 3 增强** |
| C. 页面标题文本 | `SubtitleViewHook` 已在扫视图树（liveLines） | 可能（页面本地渲染） | RN 视图结构脆弱、归一化困难 ⇒ 留作**确认通道**，不当主判据 |
| D. 播放身份指纹 `(tc, durMs, idx)` | 状态 Map，现有管道，**零新 hook** | ✓ | **选它** |

**碰撞分析**：不同作品要同时满足「音轨数相同、序号相同、时长相同到毫秒」才会误命中——除非是同一份音频被反复发售（合集再录）这类边缘。且日志全量记录每次命中（identity + workKey + cues 数），Ari 可事后抽验；若还不能接受，Phase 3 可加标题确认。

## 5. 详细设计

### 5.1 写入（在线）

- **接入点**：`SubtitleRepository.loadFromJsonArrayInternal` 末尾（持有 lock 时快照 `observedPlaylistSelection`），异步入队。
- **落盘内容**：JSON 原文（实测 60–80KB / 324 cues 上限）+ 索引条目：
  `{workKey, tc, idx, durMs(待盖), cues, bytes, hash, createdAt, lastUsedAt}`。
- **`(tc, idx)` 来源**：加载那一刻的**选择键**——code 1004 已实证它在音源装载期就可读，正是新轨 JSON 到达时唯一可用的标签。
- **`durMs` 延迟盖章**：JSON 到达时时长往往还是 0（code 1004 的同一现象），所以条目先留 `durMs=0`（不可匹配的孤儿）；等**权威身份读数**到来（`noteObservedPlaylistIdentity`），若与条目 `(tc, idx)` 相同且 `cuesWorkKey` 一致 ⇒ 补盖。
- **自愈**：在线重播同轨 ⇒ 同 `(workKey, tc, idx)` 条目覆盖重写（字幕被 DLsite 更新也能自愈）。

### 5.2 索引与淘汰

- `index.json`（原子写）+ 每轨一个文件，文件名 = `md5(workKey|tc|idx)`。
- 内存 `HashMap<Long, Entry>`，键 = 身份打包值（与 `makeIdentity` 同口径）。
- LRU（`lastUsedAt`）+ 容量上限：默认 128MB（≈1600+ 轨），可配 16/64/256/关闭。
- 损坏容忍：索引损坏 ⇒ 重建为空；单文件损坏 ⇒ 删条目按未命中处理。**任何 I/O 失败都静默降级 + 日志，绝不抛回宿主。**

### 5.3 读取（断网）

- **接入点 1（主）**：`onTrackChanged(...)` 里 `tryResumeFromCache` 返回 false 之后、进入 pending 之前；`newIdentity != 0` 时查盘。
- **接入点 2（兜底）**：`resolvePendingTrack` 裁决点前再查一次（防身份读数迟到/抖动）。
- **命中后**：异步读文件 ⇒ `loadFromJson(text, workKey, fromDisk=true)`（`fromDisk` 跳过回写防递归）⇒ 现有复位逻辑全部白嫖：`pendingToken++`、撤销挂起/软裁决/上一轨隔离、`notifyObservers()`。
- **未命中**：现有流程一字不变。

### 5.4 标签竞态的防护栈（主要残余风险）

**现象**：冷 JSON 到达慢（实测 5.5–15.6s），期间用户又切了轨（连播/手滑），到达时的选择键已是**被切后**的轨 ⇒ 条目张冠李戴。

| 缓解 | 做法 |
|---|---|
| ① cue 时间轴交叉校验 | 条目 `max(end_time)` 不得超过所盖 `durMs + 2s`，否则拒绝盖章（留 `durMs=0` 孤儿，永不命中） |
| ② 内容哈希去重 | 同一 workKey 下两条目内容哈希相同而 `(idx/dur)` 不同 ⇒ 后者覆盖时删除前者（误标条目在正确轨重播时被清掉） |
| ③ 全量日志 | 命中时打 `identity + workKey + cues`，可抽验 |

**残余风险**（如实记账）：竞态发生后、正确轨重播前，若断网播到被误盖的轨 ⇒ 显示错字幕。概率低、可自愈、有日志。若 Ari 不能接受 ⇒ 上 Phase 3 标题确认通道。

## 6. 风险登记表

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 指纹误命中 ⇒ 显示错字幕 | 低 | 高 | §5.4 三件套；毫秒精度；命中日志 |
| 假设 A2 不成立（断网时状态 Map 不输出身份） | 低 | 功能失效 | 真机第一步就验；不成立则退化到方案 B/C |
| 宿主清数据 / 卸载 ⇒ 缓存清空 | 中 | 降级为现状 | 无需处理，文档说明即可 |
| 磁盘满 / 写失败 | 低 | 无缓存 | 静默降级 + 日志，不抛异常 |
| 与 973/980/1004–1006 状态机互踩 | 中 | 假阴性回归 | 接入点排在内存缓存之后；磁盘命中复用 `loadFromJsonArrayInternal` 复位语义；回归用例全跑 |
| SystemUI 进程误写（拿到的是 systemCtx） | 低 | 脏数据 | 缓存只在宿主进程初始化（包名判等守卫），SystemUI 不碰盘 |
| 容量爆炸 | 低 | 占空间 | 默认 128MB + LRU |
| DLsite 更新字幕 | 低 | 显示旧字幕 | 在线重播自愈覆盖 |

## 9. 验证计划

- **单测**：纯函数层（指纹打包、LRU 淘汰、索引序列化 round-trip）。
- **真机 A（主路径）**：下载作品 → 在线播一遍（确认落盘日志）→ 飞行模式 → 播放 ⇒ 期望 `disk cache hit` + 字幕显示；与在线截图逐 cue 对比。
- **真机 B（竞态）**：在线冷启动后快速连切多轨，检查索引无错盖（时间轴校验拒绝日志）。
- **真机 C（回归）**：在线全部现有用例（换轨 / 假换轨 / 反向切回 / 换作品 / 无字幕轨）——一条不许退。
- **真机 D（边界）**：清宿主数据后降级正常；容量打爆后 LRU 生效。
- **dex 层**：verify 脚本核对新常量。

## 10. 需真机验证的假设 & 待 Ari 确认

**假设（真机第一步验）**：
- A1：断网 + 已下载作品可正常打开播放页并播放（官方功能，基本确定）。
- A2：断网时状态 Map 仍输出 `(trackCount, duration, currentIndex)`（高度可能：这是播放器自身状态，不依赖网络；但必须实证）。
- A3：下载版与在线版的时长读数一致（若下载是同一文件则成立；A2/A3 都关系到指纹可靠性）。

**待确认**：
1. 缓存范围默认「全部在线播过的轨」自动 LRU，可以吗？（设置页进程受 SELinux 限制读不到宿主的 `Android/data` 目录，自动管理最稳。）
2. 容量上限默认 128MB 合适吗？
3. 断网命中时字幕**立即显示**（不等网络）可以吗？在线慢 JSON 会被缓存抢先——内容相同无视觉差异，但取证口径变了。
4. 身份口径认不认 `(trackCount, durationMs, currentIndex)` 指纹？想更稳就投入 Phase 3 的标题/URI 确认通道。
5. 顺带观察：飞行模式下 App **自带字幕**显示正常吗？（不影响方案，只决定这功能是「对齐 App」还是「独有能力」。）
